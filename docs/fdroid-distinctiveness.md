# Sonveil: F-Droid distinctiveness response

Prepared 2026-10-02 against Sonveil v1.3.11 (version code 31).

## Suggested reply to the reviewer

Thank you for raising the overlap with existing clients. Sonveil's specific added value is a headphone-correction workflow integrated into a self-hosted music player:

- **Offline AutoEQ preset search:** the APK bundles 8,849 measurement presets, including measurement-source and rig information. Selecting a preset applies its graphic or parametric filters and corresponding preamp. This catalog is usable without contacting an external preset service. These are measurement entries, not 8,849 distinct headphone models. [Catalog implementation](https://github.com/exquisiteskink/Sonveil/blob/v1.3.11/app/src/main/java/app/sonveil/music/data/player/AutoEqCatalog.kt), [preset application](https://github.com/exquisiteskink/Sonveil/blob/v1.3.11/app/src/main/java/app/sonveil/music/ui/settings/SettingsScreen.kt).
- **Editable parametric EQ inside the player:** users can adjust frequency, gain, Q, filter type, and preamp, or use a 10-band graphic EQ. The filters process decoded audio inside Sonveil's playback pipeline, so headphone correction requires no separate equalizer app, root, Shizuku, or ADB setup. [Audio processor](https://github.com/exquisiteskink/Sonveil/blob/v1.3.11/app/src/main/java/app/sonveil/music/data/player/GraphicEqProcessor.kt), [playback integration](https://github.com/exquisiteskink/Sonveil/blob/v1.3.11/app/src/main/java/app/sonveil/music/data/player/PlaybackService.kt).
- **Saved EQ per detected output:** Sonveil saves the EQ configuration for the connected output and restores the corresponding profile when detected outputs change. For example, Bluetooth headphones and a USB output can retain different corrections, with a separate speaker profile. [Output monitor](https://github.com/exquisiteskink/Sonveil/blob/v1.3.11/app/src/main/java/app/sonveil/music/data/player/AudioOutputMonitor.kt), [profile persistence](https://github.com/exquisiteskink/Sonveil/blob/v1.3.11/app/src/main/java/app/sonveil/music/data/player/PlayerSettings.kt).

These capabilities serve users who host their library on Navidrome/Subsonic/OpenSubsonic and want to select and tune a headphone correction within the same app they use to stream and play downloaded music.

I recognize the existing overlap: [Ultrasonic](https://f-droid.org/en/packages/org.moire.ultrasonic/) and [Tempus](https://f-droid.org/en/packages/com.eddyizm.degoogled.tempus/) already offer ReplayGain; [Tempus also advertises an equalizer](https://github.com/eddyizm/tempus/blob/main/README.md); [Chora](https://f-droid.org/packages/com.craftworks.music/) already offers Material 3 and Android Auto. Sonveil's case for inclusion rests on the integrated AutoEQ, editable parametric processing, and output-profile workflow described above. These features are already implemented in the submitted release.

For a concrete comparison with Navic, I checked its Android source at commit `913244f29a321ba0d343e452e61725c88b28686d`. Its [built-in EQ](https://github.com/ssalggnikool/Navic/blob/913244f29a321ba0d343e452e61725c88b28686d/app/src/main/kotlin/paige/navic/exoplayer/impl/ExoEqualizerManager.kt) uses Android's standard `audiofx.Equalizer` and the bands provided by the device. Its [saved configuration](https://github.com/ssalggnikool/Navic/blob/913244f29a321ba0d343e452e61725c88b28686d/app/src/main/kotlin/paige/navic/domain/model/settings/EqualizerConfig.kt) contains band levels, band count/range, and mode; its [manager](https://github.com/ssalggnikool/Navic/blob/913244f29a321ba0d343e452e61725c88b28686d/app/src/main/kotlin/paige/navic/domain/manager/EqualizerManager.kt) persists one configuration. I found no built-in AutoEQ catalog, editable parametric filters, or per-output EQ profiles in that source. Navic also supports attaching an external EQ; Sonveil provides the described correction workflow within its own player.

Would this provide sufficient distinct value under the inclusion policy? If there is a listed Subsonic client with this same combined workflow, please identify it so I can provide a direct comparison.

## Comparison supporting the reply

F-Droid's [inclusion policy, Quality Control](https://f-droid.org/en/docs/Inclusion_Policy/#quality-control), asks for unique value and meaningful improvements over minor rebranding. A different appearance, privacy claims, or basic protocol support alone would be a weak justification.

The table summarizes published descriptions reviewed on 2026-10-02, with a targeted source review of Navic added after the owner requested that comparison. It is **not** a complete code audit of every competing app. Missing documentation does not establish a missing feature. The broader distinction proposed here is an inference from those descriptions and Sonveil's implementation; it is not a verified claim that Sonveil is the only app with these capabilities.

| --- | --- | --- |
| [Ultrasonic](https://f-droid.org/en/packages/org.moire.ultrasonic/) | Subsonic streaming, downloads, Material You, multiple servers; 4.9.0 adds ReplayGain. | Explain the AutoEQ/parametric/output-profile workflow. ReplayGain, downloads, and Material styling are shared capabilities. |

Its [upstream README](https://github.com/eddyizm/tempus/blob/main/README.md) also advertises a built-in or third-party equalizer. | Distinguish headphone measurement presets, editable parametric filters, and automatic restoration per detected output. A generic claim of having an equalizer is insufficient. |

Sonveil's proposed added value is bringing this correction workflow directly to a self-hosted Subsonic library player.

## Evidence and limits

- Counted the JSON catalog directly: **8,849 entries**, **6,032 distinct name strings**. Name strings are not a verified count of distinct physical headphone models.
- Checked the UI, preset loader, filter processor, playback integration, and output-profile persistence. These files have no differences between the submitted v1.3.11 tag and the current checkout.
- Downloaded Navic's public source at `913244f29a321ba0d343e452e61725c88b28686d`, read its EQ manager/configuration/UI and playback integration, and searched Android source for AutoEQ, parametric filters and output-profile handling. The EQ manager saves a single `equalizer_config`; the reviewed source contained no matching AutoEQ/parametric/output-profile implementation. This comparison covers that GitHub commit, not every historical release, another fork or an external EQ app a user might install.
- The catalog is bundled preset data, not Sonveil's original measurements or a real-time headphone measurement feature. Attribution is documented in [third-party-assets.md](third-party-assets.md).
- Output selection uses Android's connected-device list and a priority rule, not a measurement of the actual routed AudioTrack device. Avoid promising perfect route detection when several devices are connected, or identification of every passive wired headphone model.
- The processor handles 16-bit and float PCM; unsupported PCM encodings bypass it. Original-file streaming does not establish bit-perfect output or exclusive USB DAC access. Those are not supported differentiation claims.
- This work inspected source and documentation; it did not perform new device playback tests or re-run the build.
- The exact reviewer comment could not be retrieved: the public merge-request page failed to load and the GitLab notes API returned HTTP 401. The owner reports a comparison to apps already listed, without specific names. This response addresses that reported concern without attributing additional statements to the reviewer.
- This is a local draft. It has not been posted to GitLab.
